# VocaLoop AI — 파일에서 단어장 가져오기

## 문제

VocaLoop에는 AI에게 말로 일을 시키는 자리가 없다. 단어 등록, 학습 조언, 시험지 생성처럼 AI가 맡을 만한 일이 각각 버튼과 모달에 흩어져 있거나 아직 없다.

그중 가장 먼저 필요한 것은 단어장 파일 가져오기다. 사용자는 교재 부록 PDF, 학원에서 받은 엑셀, 직접 정리한 CSV 같은 단어 목록을 이미 가지고 있는데, 지금은 이미지 스크린샷으로만 가져올 수 있다. 수백 개 단어를 한 화면씩 찍어 올리거나 한 단어씩 입력해야 한다.

## 원하는 결과

- 웹 상단 네비게이션의 Settings 자리에 **AI** 탭이 있다. Settings는 헤더 오른쪽 계정 아이콘으로 들어간다. 모바일 하단 4칸 네비게이션도 같은 구성이다.
- AI 탭은 대화형 화면이다. 사용자가 PDF·CSV·XLSX 파일을 첨부하면(메시지는 선택) AI가 파일에서 영어 단어를 뽑아 **"N개 단어를 '폴더명' 폴더로 만들까요?"** 카드를 대화 안에 보여 준다.
- 카드에서 단어를 빼거나 고치고, 폴더를 바꾸고, 저장을 누르면 단어가 그 폴더에 저장된다. 저장 전에는 단어·폴더를 DB에 쓰지 않는다.
- 폴더는 기본이 **새 폴더 만들기**(AI가 파일 내용·파일명에서 이름을 제안). 사용자가 메시지에서 기존 폴더를 지목하면("TOEFL 폴더에 넣어줘") 그 폴더가 미리 선택되고, 카드에서도 기존 폴더로 바꿀 수 있다.
- 파일에 한국어 뜻이 함께 있으면 그 뜻이 `meaning_ko`로 저장된다. 발음·품사·예문·유의어는 기존 AI 단어 분석이 채운다.
- 이미 단어장에 있는 단어는 새로 만들지 않고 대상 폴더에만 넣는다 (기존 여러 단어 추가와 같은 규칙).
- 한 카드는 최대 200개. 파일에 그보다 많으면 200개씩 카드를 나눠 이어서 진행한다 — 첫 200개를 저장하면 "나머지 N개도 가져올까요?"로 다음 카드가 온다.
- 진행 상황(분석 중 n/N, 저장 중)과 결과 요약(저장·폴더 추가·중복·실패 개수)이 대화 안에 남는다.
- 대화는 서버에 저장된다. 새로고침하거나 다른 기기에서 열어도 이전 대화와 카드(저장됨·취소됨 상태 포함)가 그대로 보인다.
- 대화를 여러 개 둘 수 있다. 목록에서 고르고, 새 대화를 시작하고, 이름을 바꾸고, 삭제한다. 새 대화의 이름은 첫 메시지·첨부 파일명에서 자동으로 붙는다.
- AI 탭은 아직 못 하는 일(단어 검색, 학습 조언, 시험지)을 할 수 있는 것처럼 보이지 않는다. 지금 할 수 있는 일을 첫 화면에서 말해 준다.

## 영향 범위

- 사용자: 웹 로그인 사용자 전부. 네비게이션이 바뀌므로 모든 화면에 닿는다.
- 프론트엔드: `Header`, `App.jsx` 라우팅(`/ai`), 새 AI 화면과 대화 컴포넌트, 기존 `handleBulkAddWords` 경로 확장(파일 뜻 전달).
- 백엔드: 파일 업로드 → 단어 추출 엔드포인트 신설(기존 `/api/vocabulary-imports/screenshot/extract`와 같은 계열). AI 대화·메시지 저장 테이블과 API 신설. PDF·XLSX 파싱용 Python 의존성 추가.
- DB: 대화·메시지 테이블 추가. 기존 테이블은 바꾸지 않는다.
- iOS 앱: 이번에는 손대지 않는다. 다만 백엔드 API는 나중에 iOS도 쓸 수 있게 클라이언트에 종속되지 않는 형태로 만든다.
- 결정 권한: Minjae Park.

## 제약

- 파일 파싱과 단어 추출은 서버의 Codex CLI로만 한다. 브라우저 API 키에 의존하지 않는다 (이미지 가져오기와 같은 원칙).
- 텍스트가 없는 스캔 PDF는 이번에 지원하지 않는다. 사용자에게 "텍스트가 없는 PDF"라고 알리고 이미지 가져오기를 안내한다.
- 카드당 단어 200개. 단어 분석이 6개씩 순차라 200개면 수 분이 걸리므로 진행 상황을 반드시 보여 준다.
- 파일 크기 상한 100MB. 운영 nginx의 `client_max_body_size`가 이보다 작으면 거기서 먼저 막히므로 배포 전 확인한다 (저장소 안 `nginx.conf`는 템플릿이라 실제 값은 서버에서 봐야 한다).
- 기존 이미지 가져오기, 여러 단어 추가 모달, 단어 저장 규칙(중복 처리, 폴더 배정)은 그대로 둔다.
- CI 게이트 `npm run build`, `pytest backend/tests -q`를 통과한다.

## 범위 밖

- 단어 검색, 학습 조언, 시험지 만들기 — 다음 단계. 이번에는 대화 화면의 뼈대, 대화 저장·관리, 파일 가져오기만.
- 여러 파일 동시 첨부, 이미지 파일 첨부(기존 모달이 있다), 스캔 PDF OCR.
- iOS 앱 UI.

## 열린 질문

- (답) 형태: 대화형 어시스턴트. 플랫폼: 웹만. 저장 전 확인 카드를 둔다. 파일의 뜻을 우선 쓴다.
- (답) Settings 탭 → 헤더 계정 아이콘으로 이동, 그 자리에 AI 탭.
- (답) 카드당 200개, 넘으면 200개씩 이어서. 기존 폴더 합치기는 명시적 요청 때만, 기본은 새 폴더. 대화는 서버 저장.
- (답) 파일 상한 100MB. 대화는 여러 개 — 목록·새 대화·이름 바꾸기·삭제 지원.
