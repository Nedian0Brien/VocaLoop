# 빠른 단어 입력 대기열 설계

## 목표

사용자가 단어 하나의 AI 분석과 저장이 끝날 때까지 기다리지 않고, 일반 단어 입력창에서 다음 단어를 계속 입력할 수 있게 한다.

입력은 즉시 받아들이되 AI 분석과 저장은 한 번에 하나씩 처리한다. 여러 AI 요청을 동시에 실행해서 서버 부하를 늘리거나 결과 순서가 뒤섞이는 방식은 사용하지 않는다.

## 현재 동작

일반 단어 추가는 `useVocabularyCommands`의 `handleAddWord`가 맡는다. 이 함수는 다음 순서로 동작한다.

1. 현재 입력값을 읽는다.
2. `isAnalyzing`을 `true`로 바꾼다.
3. AI 분석이 끝날 때까지 기다린다.
4. 분석 결과를 `/api/words`에 저장한다.
5. 저장이 끝난 뒤 입력값을 비우고 `isAnalyzing`을 `false`로 되돌린다.

`VocabularyDashboard`는 `isAnalyzing`이 `true`인 동안 입력창과 Generate 버튼을 비활성화한다. 이미지 가져오기와 여러 단어 추가 버튼도 함께 잠긴다. 이 때문에 사용자는 다음 단어를 입력할 수 없다.

별도의 `BulkWordAddModal`과 `runBulkWordAdd`에는 여러 단어를 모아서 처리하는 흐름이 이미 있다. 이번 변경은 해당 모달을 대체하지 않는다. 일반 입력창에서 단어를 하나씩 빠르게 입력하는 흐름만 고친다.

## 사용자 흐름

1. 사용자가 일반 입력창에 단어를 입력하고 Enter 또는 Generate를 누른다.
2. 앱은 단어와 현재 선택된 저장 폴더를 하나의 작업으로 캡처한다.
3. 작업이 대기열에 들어가면 입력창을 즉시 비우고 다시 포커스한다.
4. 사용자는 첫 단어의 생성 완료를 기다리지 않고 다음 단어를 입력한다.
5. 앱은 대기열의 맨 앞 작업부터 AI 분석과 저장을 순차 실행한다.
6. 저장된 단어는 기존 방식대로 단어 목록에 추가된다.
7. 한 작업이 실패해도 해당 작업만 실패로 표시하고 다음 작업을 계속 처리한다.

## 상태와 데이터 계약

대기열의 각 작업은 최소한 다음 정보를 가진다.

```js
{
  id,
  word,
  folderId,
  status,
}
```

- `id`: React 렌더링과 작업 추적에 쓰는 클라이언트 식별자
- `word`: 입력 시점에 공백을 제거한 단어
- `folderId`: 입력 시점에 선택된 폴더 ID 또는 `null`
- `status`: `queued`, `processing` 중 하나

입력 이후 폴더 선택이 바뀌더라도 이미 대기 중인 작업의 `folderId`는 바뀌지 않는다.

서버 API와 저장 payload는 변경하지 않는다. 각 작업은 기존 `generateWordData`와 `createWord`를 그대로 사용한다.

## 처리 규칙

- 동시에 처리하는 일반 입력 작업은 1개로 제한한다.
- 새 작업은 처리 중인 작업 뒤에 추가한다.
- 대기열의 실제 저장소는 ref로 두고 React state는 화면 표시용 복사본으로 사용한다. enqueue는 ref에 작업을 동기적으로 추가하고 worker 시작 함수를 직접 호출한다.
- 전용 worker 하나만 대기열을 소비한다. worker 시작 함수는 렌더링과 독립된 active ref를 즉시 잠가 React StrictMode나 effect 재실행이 같은 작업을 두 번 처리하지 못하게 한다.
- worker는 맨 앞 작업을 `processing`으로 바꾼 뒤 완료될 때까지 제거하지 않는다. 완료 후 해당 작업을 제거하고 다음 작업을 읽는다.
- worker가 큐를 비운 뒤 active ref를 해제할 때는 ref의 최신 대기열을 다시 확인한다. 그 사이 들어온 작업이 있으면 worker 시작 함수를 다시 호출해 종료 시점의 enqueue가 남지 않게 한다.
- 입력값은 작업 등록 직후 비운다.
- 작업 등록 직후 입력창에 다시 포커스한다.
- 빈 문자열은 등록하지 않는다.
- 로그인 상태와 AI provider 접근 가능 여부는 작업 등록 전에 확인한다.
- 대기열 처리 중에도 일반 입력창과 폴더 선택을 사용할 수 있다.
- 한 작업이 실패해도 대기열 전체를 중단하지 않는다.
- 성공한 작업은 대기열에서 제거한다.
- 실패한 작업은 해당 단어가 포함된 오류 알림을 표시한 뒤 대기열에서 제거한다. 첫 버전에는 실패 카드를 남기거나 자동 재시도와 영구 실패 목록을 추가하지 않는다.
- dashboard에서 다른 화면으로 이동해도 App의 명령 hook이 유지되는 동안 대기열 처리는 계속한다.
- 로그아웃하거나 로그인 사용자가 바뀌면 대기 중인 작업을 모두 비운다. 이미 AI 분석 중인 작업은 session generation 값을 확인해 `createWord` 호출로 넘어가지 않게 한다.
- 로그아웃 전에 `createWord` 요청이 이미 서버에 도착한 경우에는 클라이언트가 DB commit을 취소할 수 있다고 보장하지 않는다. 이 경우 이전 세션의 응답으로 현재 화면 상태나 알림을 갱신하지 않는다.

## 화면 동작

기존 단어 추가 카드의 구조, 입력창, 폴더 선택, Generate 버튼은 유지한다.

- Generate 버튼은 현재 입력값이 비어 있을 때만 비활성화한다.
- 작업을 등록할 때 버튼에 장시간 로딩 상태를 유지하지 않는다.
- 기존 로딩 카드 영역에는 처리 중인 작업과 대기 중인 작업을 표시한다.
- 처리 중인 작업은 기존 스피너와 `단어 생성 중...` 상태를 사용한다.
- 대기 중인 작업은 단어와 대기 상태를 구분할 수 있게 표시한다.
- 자동완성은 현재 입력값만 기준으로 계속 동작한다.
- 이미지 가져오기와 여러 단어 추가는 일반 입력 대기열이 모두 끝날 때까지 기존처럼 잠근다.
- 일반 입력도 기존 대량 저장 작업이 진행 중일 때는 잠근다. 일반 대기열과 `runBulkWordAdd`가 같은 단어 목록과 AI provider를 동시에 사용하지 않게 한다.

새 카드 셸이나 별도의 전역 작업 패널은 만들지 않는다.

## 오류 처리

작업별 오류를 분리한다.

- AI 분석 실패: 해당 단어의 실패 알림을 표시하고 다음 작업으로 넘어간다.
- 저장 API 실패: 해당 단어의 실패 알림을 표시하고 다음 작업으로 넘어간다.
- AI provider 접근 불가: 작업을 등록하지 않고 기존 설정 안내를 표시한다.
- 화면 이동: App의 명령 hook이 유지되므로 진행 중인 작업을 계속 처리한다.
- 로그아웃이나 사용자 변경: 대기 작업을 비우고, 이전 session generation에서 AI 분석을 마친 작업은 새 저장 요청을 시작하지 않는다. 이미 전송된 저장 요청의 서버 처리는 취소 대상으로 삼지 않으며 응답만 무시한다.

실패를 성공처럼 보이게 하는 fallback은 넣지 않는다.

## 테스트

프론트엔드 테스트로 다음 계약을 고정한다.

- 첫 단어의 AI 분석이 끝나기 전에 두 번째 단어를 입력하고 제출할 수 있다.
- 입력값은 작업 등록 직후 비워진다.
- 작업 등록 뒤 입력창이 다시 포커스된다.
- AI 분석은 두 작업에 대해 동시에 실행되지 않고 등록 순서대로 실행된다.
- React StrictMode에서 같은 작업을 두 번 분석하거나 저장하지 않는다.
- 각 작업은 입력 시점의 폴더 ID를 저장한다.
- 첫 작업이 실패해도 두 번째 작업은 계속 분석하고 저장한다.
- 처리 중인 작업과 대기 중인 작업이 화면에 표시된다.
- 처리 도중 새 작업을 넣어도 현재 작업 뒤에 이어서 처리한다.
- worker가 종료되는 경계에서 새 작업을 넣어도 작업이 남지 않고 새 worker가 처리한다.
- 처리 중에도 새 입력값에 대한 자동완성이 열린다.
- 일반 대기열이 남아 있는 동안 이미지 가져오기와 여러 단어 추가가 잠긴다.
- 대량 저장 중에는 일반 단어 입력이 잠긴다.
- AI 분석 중 로그아웃하면 대기 작업이 사라지고 해당 분석 결과로 `createWord`를 호출하지 않는다.
- 저장 요청 전송 뒤 로그아웃하면 이전 세션 응답으로 단어 목록이나 알림을 갱신하지 않는다.
- 기존 단일 단어 추가와 여러 단어 추가 테스트가 계속 통과한다.

검증은 변경된 테스트부터 실행한 뒤 전체 프론트엔드 테스트, 프로덕션 빌드, 백엔드 테스트 순서로 진행한다. 브라우저에서는 390px, 768px, 1280px 화면에서 연속 입력과 대기 상태를 확인한다.

## 변경 범위

변경 대상:

- 일반 단어 입력 명령의 상태와 순차 처리
- 일반 입력 폼의 disabled 조건과 작업 상태 표시
- 관련 프론트엔드 테스트

변경하지 않는 대상:

- `/api/words` 계약과 백엔드 모델
- AI provider와 모델 선택
- `BulkWordAddModal`의 저장 방식
- 이미지 단어 가져오기
- 폴더 생성·수정·삭제
- 단어 카드 디자인과 학습 기능

## 제외 범위

첫 버전에는 다음을 추가하지 않는다.

- 동시 AI 분석
- 서버 측 background job
- 새로고침 후 대기열 복원
- 작업 취소와 순서 변경
- 자동 재시도
- 대기열 처리 속도 설정
