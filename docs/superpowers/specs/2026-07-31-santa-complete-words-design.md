# 산타형 Complete the Words 출제 설계

## 목표

현재 VocaLoop의 Complete the Words는 120~160단어짜리 학술 지문에서 4~10자 단어를 고른 다음, 단어 길이에 따라 앞 1~3자를 보여줍니다.

이번 변경에서는 지문을 70~100단어로 줄입니다. 짧은 기능어와 내용어를 함께 출제하고, AI가 단어마다 공개할 글자 수를 `revealCount`로 정합니다. 화면 구조와 채점 방식은 그대로 둡니다.

## 출제 형식

한 문항은 70~100단어, 최소 4문장으로 구성합니다. 첫 문장과 마지막 문장은 빈칸 없이 문맥을 제공합니다. 빈칸은 가운데 문장에만 배치합니다.

문항당 빈칸은 지금처럼 10개입니다. 표적어는 2~10자의 영단어로 제한합니다. 이 중 2~4개는 문맥과 문법적 연결을 확인하는 짧은 기능어로 고르고, 나머지는 지문의 의미를 구성하는 내용어로 고릅니다. 같은 단어를 한 문항에서 두 번 출제하지 않습니다.

## 데이터 계약

문항은 기존 필드를 유지합니다.

```json
{
  "paragraph": "첫 문장. 가운데 {{1}} 문장. 마지막 문장.",
  "fullParagraph": "첫 문장. 가운데 완성된 문장. 마지막 문장.",
  "blanks": []
}
```

`paragraph`는 표적어를 `{{1}}`, `{{2}}` 같은 placeholder로 바꾼 지문입니다. `fullParagraph`는 빈칸이 없는 완성 지문입니다.

각 빈칸은 다음 정보를 가집니다.

```json
{
  "id": 1,
  "answer": "creating",
  "revealCount": 4
}
```

`answer`는 완전한 정답 단어입니다. `revealCount`는 고정해서 보여줄 앞글자 수입니다. 나머지 글자는 사용자가 입력합니다.

`revealCount`는 1 이상의 정수이며 `answer`의 영문 글자 수보다 작아야 합니다. AI가 값을 빼먹거나 범위를 벗어난 값을 반환하면 기존 길이 규칙을 사용합니다. `revealCount`가 없는 기존 저장 문항도 같은 fallback으로 계속 열립니다.

## 생성 흐름

AI는 완성된 지문, `{{1}}` 형식의 placeholder가 들어간 지문, 정답 단어, `revealCount`를 함께 반환합니다. placeholder는 저장과 렌더링을 위한 내부 표현입니다. 실제 문제에서는 `answer`의 앞 `revealCount`글자를 고정하고 나머지를 입력 칸으로 바꿉니다.

AI는 단어 난이도와 문맥 단서를 보고 공개할 글자 수를 고릅니다. 기본 범위는 다음과 같습니다.

- 2~3자 단어: 1자 공개
- 4~6자 단어: 2~3자 공개
- 7~10자 단어: 2~4자 공개

모든 단어에는 입력할 글자가 하나 이상 남아야 합니다.

## 검증과 fallback

새로 생성한 문제는 저장하고 화면에 표시하기 전에 구조를 검사합니다.

- 요청한 문항 수와 실제 문항 수가 같다.
- 각 `fullParagraph`가 70~100단어, 최소 4문장이다.
- `paragraph`의 첫 문장과 마지막 문장에는 placeholder가 없다.
- 각 문항에 중복되지 않은 빈칸이 정확히 10개 있다.
- placeholder ID와 `blanks[].id`가 빠짐없이 대응한다.
- 각 `answer`가 2~10자의 영단어다.
- 10개 중 2~4개가 4자 이하의 짧은 기능어다.

짧은 기능어 여부는 프롬프트의 분류를 그대로 믿지 않고 앱의 고정 목록으로 판별합니다. 목록에는 `as`, `at`, `by`, `if`, `in`, `of`, `on`, `or`, `so`, `to`, `up`, `yet`, `and`, `but`, `for`, `nor`, `the`, `with`, `from`을 둡니다. 목록에 있으면서 4자 이하인 단어만 기능어 수에 포함합니다.

단어 수는 `fullParagraph`의 앞뒤 공백을 제거한 뒤 연속 공백을 기준으로 나눠 계산합니다. 문장은 영문 마침표, 물음표, 느낌표를 종결 부호로 삼아 나누고 빈 조각은 제외합니다. `paragraph`도 같은 기준으로 나눈 뒤 첫 문장과 마지막 문장에 `{{숫자}}` placeholder가 없는지 확인합니다.

구조 검증에 실패하면 문제를 저장하거나 일부만 보여주지 않습니다. 기존 `useToeflQuizSession`의 오류 상태로 넘겨 사용자가 실패 이유를 보고 다시 생성할 수 있게 합니다. 자동 재시도는 AI 호출 시간과 direct provider 비용을 사용자의 동의 없이 늘릴 수 있으므로 이번 범위에 넣지 않습니다.

기존 저장 문항은 새 출제 구조 검증을 거치지 않습니다. `prepareCompleteQuestions`의 호환 경로로 바로 읽습니다.

각 빈칸의 `revealCount`는 다음 순서로 검사합니다.

1. 정수인지 확인합니다.
2. 1 이상인지 확인합니다.
3. 정답의 영문 글자 수보다 작은지 확인합니다.
4. 유효하면 그대로 사용합니다.
5. 없거나 잘못된 값이면 기존 `getPrefixRevealCount` 결과를 사용합니다.

잘못된 `revealCount` 때문에 문제 전체를 버리지는 않습니다. 정답 단어와 지문은 유지하고 공개 글자 수만 기존 규칙으로 보정합니다.

준비가 끝난 뒤에는 `blank.segments`가 철자 공개 범위의 단일 출처입니다. 입력 가능 위치, 정답 판정, 사용자 답안 재구성은 모두 이 값을 사용합니다. `buildCompleteUserAnswers`를 포함한 후속 경로에서 `answer`만 보고 segment를 다시 계산하지 않습니다.

## 저장과 복습 호환성

TOEFL 문제 자산은 `payload`를 JSON 객체로 저장합니다. `blanks`에 `revealCount`를 추가해도 데이터베이스 스키마를 바꿀 필요가 없습니다.

새 문제는 `revealCount`까지 저장하므로 다시 풀 때도 같은 철자 마스크가 나옵니다. 기존 문제는 현재 길이 규칙으로 렌더링합니다. 시도 결과와 복습 항목은 계속 `answer`와 사용자 입력으로 만들기 때문에 백엔드 복습 계약도 유지됩니다.

## 테스트

프론트엔드 테스트로 다음 계약을 고정합니다.

- 생성 프롬프트가 70~100단어와 최소 4문장을 요구한다.
- 첫 문장과 마지막 문장에 빈칸을 두지 않도록 요구한다.
- 표적어 길이를 2~10자로 요구한다.
- 10개 중 2~4개의 짧은 기능어를 요구한다.
- JSON schema에 `revealCount`가 포함된다.
- 유효하지 않은 지문 길이, 문장 배치, 빈칸 수, 기능어 구성을 새 문제로 저장하지 않는다.
- 기존 저장 문항은 새 출제 구조 검증을 거치지 않는다.
- 유효한 `revealCount`만큼 앞글자가 공개된다.
- 빠지거나 잘못된 `revealCount`는 기존 규칙으로 fallback한다.
- 기존 저장 문항은 현재 공개 규칙을 유지한다.
- 새 문항은 저장 후 다시 열어도 같은 마스크를 유지한다.
- 사용자 답안 재구성이 `blank.segments`를 사용해 AI가 정한 공개 글자를 보존한다.
- 입력, 채점, 오답 저장, 복습 결과 테스트가 계속 통과한다.

## 변경 범위

변경 대상:

- Complete the Words 생성 프롬프트
- 새로 생성한 문제의 구조 검증
- `revealCount` 검증과 철자 segment 생성
- `blank.segments`를 사용하는 답안 재구성
- 출제 계약과 하위 호환성 테스트

변경하지 않는 대상:

- Complete the Words 화면 레이아웃
- 문항당 빈칸 10개
- 정답 채점 단위
- AI provider 호출 방식
- TOEFL 자산과 시도 API
- 데이터베이스 모델과 migration
- 다른 Reading/Writing 문제 유형

## 완료 조건

새 문제는 저장 전에 70~100단어의 문단, 빈칸 없는 첫·마지막 문장, 짧은 기능어와 내용어가 섞인 10개 빈칸을 검증해야 합니다. 각 빈칸은 단어별 `revealCount`를 사용하고, 답안 재구성까지 같은 `blank.segments`를 유지해야 합니다. 기존 저장 문제는 오류 없이 이전 규칙으로 열려야 합니다. 관련 테스트, 전체 프론트엔드 테스트, 프로덕션 빌드, 백엔드 테스트를 통과한 뒤 배포합니다. 마지막으로 실제 서비스 번들에 새 출제 계약이 포함됐는지 확인합니다.
